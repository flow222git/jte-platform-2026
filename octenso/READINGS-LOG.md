# 判讀登記表(去識別中繼資料)

版本:0.1 ｜ 建立:2026-08-04 ｜ 依據:待議題十一 · CALIBRATION schema 待辦 8
性質:**每案一列的結構化紀錄**,不是判讀報告。判讀內容、逐字引文、真實素材一律不入本檔(同 `CALIBRATION.md` 檔頭之去識別規則)。

## 為什麼要有這張表

到 2026-08-03 為止,30+ 案的判讀紀錄全部是**敘述文字**。要回答「半象佔多少」「艮出現過幾次」「動爻數跟結局有沒有關係」,都得人工逐案數一遍(討論版〈資料觀察〉四條就是這樣數出來的,誤差 ±1)。

有了這張表:

- **v0.2 的一致率有分母**(待議題一:算法定死、判定留痕)
- **資料觀察四條從觀察變可檢定**
- **雙盲與迴測有固定留痕格式**(跑過≠測過)
- 分布偏斜(如艮 0 次)可以持續追蹤而不是每次重數

## 欄位定義

| 欄 | 值域 | 說明 |
|---|---|---|
| 案號 | R+序號 | 本表流水號,與校準歷程的 #n 不同 |
| 日期 | YYYY-MM-DD | 判讀日 |
| 素材 | 名稱或代號 | 公開文獻記名;客戶與未公開素材用代號 |
| 類型 | 八型之一 | brainstorm/decision/retro/routine/bp/policy/interview/observation |
| 次型 | 見 schema | 宣言/調查/內部報告/成功敘事/法規理論文本/AI摘要轉述/聚合交付/自答題庫 |
| 成卦階 | 六爻 / 半象 / 爻象 / 三爻 / 不成 / 拒判 | 解析度階梯(非成績) |
| 內卦 · 外卦 | 八態或「—」 | 半象時只填成立的那一池 |
| 動爻數 | 0–6 或「—」 | 靜卦記 0 |
| 爻疑數 | 0–6 或「—」 | ≥3 應觸發爻疑氾濫規則 |
| 警示 | 唯用無道/空談/自產病/主體同一性/語用/G7降級/— | 觸發的警示,可複選 |
| 三值回饋 | 很像 / 部分像 / 不太像 / 未收 | 素材主人或代收者 |
| 已知結局 | 是 / 否 / 不適用 | **判讀者事前是否知道該素材的後續結局**——結局盲判的前提欄 |

### 補登說明(誠實邊界)

本表 R01–R30 為**依 `CALIBRATION.md` 敘述紀錄回填**,不是當時即時登記,因此:

- **空欄 `—` 多數代表「當時沒記」,不是「值為零」**。動爻數與爻疑數在第二輪多數案未載;三值回饋 24/30 未收。
- 「已知結局」欄是**事後判定**:公開文獻案(名人、名企、事故調查)判讀者必然事前知道結局,故填「是」;客戶與日用素材填「否」。這一欄的回填本身就說明了問題——**30 案裡有 19 案判讀者事前知道結局**。
- R23 羅馬案標「應拒未拒」:當時形式檢查全綠而出判,事後認定為半開破口(BOUNDARIES 案 4)。
- 案號與校準歷程的 #n 不對應;`CALIBRATION.md` 仍是敘事真相源,本表只是它的結構化投影。

## 使用規矩

1. **每案判讀後即時登記**,不事後補——事後補會產生本表 R01–R30 這種空欄。
2. **雙盲與迴測另加註**:標明測的是哪一層(states 八態 presence / lens 六格),並在 `CALIBRATION.md` 的收斂指標紀錄表填數字。跑過≠測過。
3. **本表只放中繼資料**。逐字引文、判讀內容、真實素材檔一律不入。
4. 客戶與未公開素材用代號,對照表不入 repo(同 CALIBRATION 檔頭規則)。
