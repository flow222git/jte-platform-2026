一

這面鏡子是什麼

一句話:八態鏡拿八態 × 道理用三角形當固定構面,讀一份素材裡的「運作」,輸出可追溯到逐字引文的映照——不評成敗、不判人、不預測。

它跟測驗端(八態能格)是兩件事、同一個家。平台第一原則講整體感不硬整合,這裡是最典型的一組:兩邊共用八態語言與誠實邊界,但輸入、對象、輸出各自獨立,不做量表對映。

八態能格(測驗端)八態鏡(透鏡端)
讀什麼人的自我感覺一份素材裡的運作
輸入25 題六點自評會議紀錄 / BP / 制度 / 觀察筆記
輸出八態剖面 + 格局 + 三拍解讀八態在場缺席 + 三角形體檢 + 判卦與轉化參考
誰在判規則引擎(確定性)AI 判定 + 機械推導(每條附引文)
場景讀法正向心理學讀法(先正面)吳怡版(坎=度險維心、震=謀定後動、離=附麗虛己)
共同紅線不預測成敗(G1)· 主詞不是「這種人」(G4)· 無引文不判定(G5)· 不排名不評分(G6)

目前狀態:內部工具。octenso/bagua-lens.html 掛 noindex、未接導覽、走登入閘,2–3 人使用;素材與報告不上傳不儲存(Worker 即時判讀不落檔),結果只留 localStorage。另有 skill 版 .claude/skills/bagua-lens/,判讀在對話裡跑,真相源可抓 GitHub raw,更新一處全部跟上。

定位討論:二元引擎(2026-07-28)

八態鏡+哲學三角是試圖把二元世界更完整解讀的引擎,藉由各種素材的學習,去理解二元的特性定義變化而不斷迭代自己並完整呈現照看解析的過程。 Simon,2026-07-28 · 原話照抄,未潤

這句話技術上站得住,而且已經長成 schema 的形狀:剛=陽、柔=陰,每爻判的就是一個二元;三爻二元組合成八態,六爻內外分池組合成 64 卦。二元確實是原子。句中三個詞各自對得上一個區塊——

  • 特性 → 剛柔判準三表(每爻的剛/柔/亢/溺各附樣態與信號)
  • 定義 → 歸格例句庫與混淆對照(定義的操作化;只增不減)
  • 變化 → 亢/溺 → 動爻 → 之卦(變化的機制,一爻變)

「哲學三角」在檔內的名字是道理用三角形,與八態的關係已定於憲法增修:三角形為體、八態為用,縱軸三層 × 橫軸八態=引擎核心。

三處要收緊,否則會踩到自己立的線:

  1. 「更完整」的合法意思是構面不漏,不是結論完整。引擎保證的是八態一態不可省略、三層一層不可省略、缺席也要列出來、未及之層明寫「素材不及,待補」。完整的是缺口清單,不是照出多少——「不成卦是有尊嚴的輸出」整條紀律靠這個區別站著。
  2. 「藉由素材的學習」不是模型餵養。素材不入 git、Worker 不落檔;累積下來的是被判讀分歧逼出來的判準修訂,而且逐條經人核准、G1–G8 凍結。準確的說法是:素材過鏡不留檔,留下的是判準。寫模糊會直接和「作答不上傳」那條北極星打架;核心凍結反而是迭代可信的前提。
  3. 二元要留逃生口,而且已經留了。爻疑兩讀並列、薄、缺席、不成卦——引擎明文允許二元判不下去。這正是與星座式二分法的分野(NEIGHBORS 窗七的自我警惕、窗十六的張力不壓平)。定位句若不寫這一層,「二元引擎」會被聽成更精緻的二分法。
候選定位句 · 待核准

八態鏡以剛柔二元為原子、以道理用三角形為縱軸、以八態為橫軸,把一份素材的運作攤成不漏構面的映照。它不追求把話說滿,而追求每一格都指得回原文,指不回就明說沒有;二元判不下去時兩讀並列,不硬選。它的迭代不來自素材本身——素材過鏡不留檔,留下的是被分歧逼出來的判準。

狀態:原始 · 待審閱(未入 canonical)。此為定位敘述,非效度宣稱;schema 仍掛 v0.1 研究假設·待考。另一處用詞待定:「照看」——照=映照無虞,「看」若被讀成照護,會碰到「八態鏡非治療」的紅線;候選改「照見」,或在文案裡把它定義死。

二

一次判讀怎麼跑

SOP 十二步,分取料 / 讀規則 / 判定 / 推導 / 輸出 / 品管六段。以下是操作地圖的濃縮,細節以 daoliyong-lens-sop.md 與 schema 為準。

素材進場→宣告(不猜)→載入真相源→逐句歸池歸格→六格判定→成卦或降級→機械反查→交叉驗證→動爻與轉化→報告組裝→三值回饋

宣告在前,不猜(G8)

必宣告兩項:素材類型(brainstorm / decision / retro / routine / bp / policy / interview / observation 八型)與判讀對象。可選兩項:目標與 TA——宣告越齊,第⑥段越準;沒宣告就不猜,寧可先問一句。另附次型註記(宣言型 / 調查型 / 內部報告型 / 成功敘事型 / 法規理論文本型),各自帶偏置聲明,預期缺席不列病理。

報告六段

  1. 缺席清單——依宣告分「警示 / 本型態預期」,附補問建議。缺席優先於失衡,失衡優先於滿格(G2)。
  2. 失衡疑似——型態不適用則註明。
  3. 強態圖景。
  4. 四系統各一句小結。
  5. 三角形體檢——理 / 用 / 道逐層 presence + 逐字引文,一層不可省略,後接三隅箴警示與一句量形描述。
  6. 判卦與轉化參考——本卦 → 變爻 → 之卦(見第五節)。

八態要逐一列在場狀態(有料 / 薄 / 缺席),一態不可省略;引不出原文就是缺席(無資料),缺席不等於弱。收尾必附道理用總綰:三層各一句判定、樣貌、功課,末一句總綰;未及之層明文「素材不及,待補」。

雙軌輸出(2026-07-22 定案)

正式交付分兩軌:白話版給素材主人與決策者,深讀版給校準與專業用(完整判定過程)。白話版七條借金字塔原理與 Gallup 報告設計:答案先行、行動標題(只讀標題就懂全篇)、紅綠燈道理用(術語零出現)、每個發現「這代表什麼 / 該注意什麼 / 怎麼做」三件套配一句原話、先力量後缺口、技術層收進附錄摺疊區、訊噪紀律。

語氣律

準而不刺——先力量後缺口、隱喻不判死(缺口意象須與在場力量同句並呈)、想像素材主人正在讀。

判完不算完:迭代模式

鏡子靠這個變準。每次判讀後收三值回饋(很像 / 部分像 / 不太像 + 哪一條最有感、哪一條最不服,記原話與理由),分歧記進 backlog 分五類:判定分歧、語彙、schema 缺口、三層判定分歧、判卦分歧(本卦 / 變爻 / 之卦分開記,六爻另記分池歸屬)。累積後才走進化流程:提案 → 逐條核准 → 修 schema + 檢查器 → 測試全綠 → 開 PR。

四

護欄 G1–G8

硬規則,編進定義層,任何 agent 不可覆寫;對⑤⑥段同樣適用。下表為 states-schema 快照,以原檔為準。

規則怎麼執行
G1只診斷能量分佈,不預測成敗禁止成功機率、成敗預言、「這樣下去會…」句式
G2缺席優先於失衡,失衡優先於滿格報告順序:無資料的態 → 失衡疑似 → 強態
G3回溯敘事僅供教學且需標明歷史素材一律加註「回溯性閱讀,不構成因果宣稱」
G4分析單位是運作,主詞不是「這種人」合法主詞:某分支 / 某個態 / 這份文件 / 這場會議
G5無證據即無判定每條判定附逐字引文;引不出來 → 判缺席(無資料)
G6禁止輸出清單總分、排名、錄取 / 投資建議、相性分數、人格標籤
G7面試 / 人事場景降級為觀察筆記只列「已收集到 / 尚無資料」的態,提示補問,不評價;不輸出⑤⑥
G8時間視角可用,因果推移禁止禁止系統主動宣稱態序推移;宣告一律使用者說,系統不猜

三種失敗要分清楚:良性失敗=誠實不成卦 / 拒判 / 降級鏈正確觸發(護欄成功);惡性失敗=界外素材仍得自信判讀且不可否證(星座化);護欄失敗=讀人紅線素材未拒判就評價了人(G4 破防,最嚴重)。

五

判卦引擎

第⑥段從「引用兩個腳本」長成本卦→變爻→之卦,再長出六爻版。整塊掛工作假說·待收斂印章,收斂前不進正式產品文案。

必附聲明

此卦由素材判讀推導,非起卦占斷;變爻是處方,不是預言。

四律

  • 非占卜律:爻由判讀而來(每爻附引文)、變由診斷與宣告而來,無一絲隨機。
  • 機械推導律:AI 只判剛柔與安動,卦由反查表自動得出;不得跳過判定直接「感覺是某卦」。同素材同判定必同卦。
  • 主詞律:卦名給運作不給人——「此局呈乾象」可以,「你是乾卦」不行。
  • 不預測律:之卦是參考路徑,不是「將會變成」;死角是結構警訊,不是命運。

三爻 / 六爻與四階降級

素材厚時自動升六爻:內池(對象內部的運作)× 外池(對外的行為與姿態)各撐三爻,內卦 × 外卦查 64 卦需求表,再做召喚對照——64 表召喚的態 × 八態在場缺席交叉驗證,召喚而缺席=首要功課,節制而正強=第一級警訊。歸池以「行為的受向」判,界隨判讀對象移動。

撐不起來就優雅降級,四階:六爻 → 局部深探(半象 / 爻象深讀,以小觀大,明標其小)→ 三爻(全料合判)→ 不成卦。不成卦是有尊嚴的輸出,附缺哪池哪爻與補問。

判讀紀律(v0.3.1 六律 + v0.3.3 回填)

律內容
證據純化引文計入某爻前先問「這是誰的行為」;判讀對象以外的行為者(委辦方 / 供應商 / 撰稿者)之品質不得計入
成爻門檻每爻 ≥2 句獨立引文(不同段落)方成爻;孤證標「薄」不成爻
同爻雙訊號亢溺同現先重驗歸格;仍衝突=該爻判動,陰陽並列兩讀標「爻疑」,異卦則並列 + 補問
爻疑氾濫爻疑爻數 ≥3 = 主體性存疑,拒判並附拆分建議
主體同一性行為者須能對彼此的行為負責或回應(同一主體、同一時段);跨主體跨世代聚合不判
動爻上限動爻 ≥4 加註「局勢多處臨界,菜單失焦」,建議先宣告目標或先處理缺席警示——不發明亂局占法

亢與溺在過勞終點外觀相同(都停不下),判別看動力來源:自驅過極=亢(剛)、被外牽走=溺(柔)。剛柔是絕對質性判定,不與他爻比強弱,全剛 / 全柔之卦必須可達。

歸格例句庫(只增不減)

  • 「不敢休 / 筆電隨身」= 用爻亢(輸出停不下)
  • 「假期存在但無法放鬆」= 道爻(餘地機制失效)
  • 「被客戶時程牽走」= 外用溺
  • 「不知為何努力 / 意義真空」= 道爻溺
  • 「怎麼做都不夠好」= 理爻溺(根基被評價體系牽走)
  • 「無對沖的極化語言」= 道爻亢,文體不豁免(雙盲 #2 裁定)
  • 「建制描述」歸內池、「交付動作」歸外池(雙盲 #2 裁定)
六

邊界:能讀多遠,在哪裡該停

2026-07-23 邊界壓測六案,配對跨線(抽象 / 尺度 / 紅線各一對,界內界外各一)。素材皆公開文獻,可入 git。

適用域三條件

判讀對象必須同時滿足:單一運作主體 × 行為證據 × 同一時段。缺一不判。

案方向結果歸類
Linux kernel 社群治理抽象 · 界內半象 · 內兌,一動爻;兌死角=素材自點名之問題,閉環正常出判
民法總則條文抽象 · 界外證據純化全攔 + 分池失錨 → 不成卦良性失敗
邱吉爾戰時內閣 1940/5尺度 · 界內半象 · 內兌 · 靜;與 Linux 成兌×兌同象異態對正常出判
羅馬帝國衰亡尺度 · 界外形式檢查全綠,每爻跨世紀衝突訊號;可合規聚合出對立判讀半開破口
Buffett–Munger 合夥紅線 · 界內半象 · 內震 · 靜(理剛 / 用柔 / 道柔)正常出判
婚姻告白 essay紅線 · 界外G7 + G4 + G6 三重護欄疊加拒判;零運作證據護欄成功

界內三案的對立卦替換測試皆不成立(結論換成對立卦說不通=有鑑別度);界外三案無一惡性輸出。三案共同點是外池薄——公開素材天然偏內部治理紀錄。

唯一實證破口:缺主體同一性時,引擎不會停。羅馬案形式檢查全綠仍可合規聚合出對立判讀;主體同一性律已於 v0.3.3 回填為判讀紀律,但 BOUNDARIES 明記誠實拒判目前靠判讀者自律,非規則。

誠實邊界:六案樣本、每方向僅一對,邊界線是「首測定位」不是定論;界內活下來不等於適用域擴張定案。六案素材由校準者選材與代宣告,存在選材偏置;案 3 / 5 帶英雄敘事與成功敘事偏置(已於各判讀註記)。

七

學理鄰居(並列相望,不做對映)

判讀紀律六律(成爻門檻 ≥2 獨立引文、證據純化)於 07-22 上線後,六爻成卦數為 0。混淆因素要講清楚:第一輪素材本來就是長篇公開文獻(股東信、事故調查報告),厚度天然高。但有一個案子直接排除「厚度說」——日用第一案是 22 萬字級的交付文本聚合,厚度是全部案例之最,仍退半象,原因是內池零證據。所以綁住六爻的不是素材夠不夠厚,是內外兩池能不能同時撐起三爻;而公開素材與交付素材天生只給得起其中一池。

這重寫了待議題四:「外池永遠薄」不是全貌——內部報告型缺外池、聚合交付型缺內池,兩者互為鏡像。真正的缺口是雙池齊備的素材類型還沒被辨識出來。

機制假說

理爻幾乎總是判剛,是文件體裁的性質,不是運作的性質。理剛的信號是「明確原則宣告」「方法論有主張」「依據直陳不繞」——任何用來記錄決策或說服他人的文件都天然充滿這些;理柔的信號是「承認知識邊界」「還在學 / 還在驗證」,在同一批體裁裡系統性稀少。理爻一旦幾乎鎖死在剛,八卦空間就有一半(理柔的巽坎艮坤)難以抵達,艮是其中最難的——它要理柔、用柔、道剛同時成立。

否證設計:補理柔錨點後重判既有案例,看巽坎艮坤的出現率是否上升。若上升,是判準的問題(可修);若不動,才是素材世界真的長這樣(要寫進誠實邊界:這面鏡子照不到止)。

觀察三 · 動爻數與結局完美分離——這是警訊不是成績

快照已列為候選假說「動爻數=嚴重度」:敗局三案(挑戰者 / Theranos / Nokia)全部六爻皆動,而靜卦(零動爻)全部落在成功敘事或友善素材。分離得太乾淨了。

完美分離在小樣本裡通常不是鑑別力的證明,而是選材與已知結局的證明。三個全動案都是眾所周知的失敗;判讀者事先知道結局。G3 要求回溯素材加註「不構成因果宣稱」,但那條註記處理的是輸出的措辭,擋不住輸入端的選擇效應。以現有證據結構,無法區分「引擎讀出了嚴重度」與「判讀者知道結局」。

否證設計:結局盲判——選判讀者不知結局的素材(或蓋掉可識別資訊、只留運作語料),再看動爻數是否仍與後續結局相關。這是目前整批資料裡最值得先做的一個測試,因為「動爻數=嚴重度」一旦沒經過這關就寫進規則,就是把選擇效應固化成判準。

觀察四 · 判準對稱,錨點不對稱

把 schema 直接數過一遍:剛柔判準三表本身是平衡的——每爻安側(剛+柔)6–7 條信號、動側(亢+溺)5–6 條。但判讀時真正拿來比對的歸格例句庫只有 8 條,扣掉 2 條程序性條目後,6 條實質錨點全部是亢或溺,零條示範「安」。依爻分:道 3、用 2、理 1,而那唯一的理層錨點是「怎麼做都不夠好=理爻溺」。

所以偏斜不在定義,在錨點。而動爻的定義正是「呈亢或溺之爻」——錨點庫只給病理範例,判讀時就會往病理靠。這與觀察二互相印證:理爻最缺錨點,也最容易滑向預設值。而且它跟語氣律「先力量後缺口」與 Gallup 優勢先行直接衝突:報告被要求從「這個組織做對了什麼」開場,爻層卻沒有任何一條「做對了長什麼樣」的工作範例。

這是四條裡最便宜的一條:例句庫只增不減、不動定義本體、不碰 G1–G8,補安側錨點是一次低風險修訂。八態的 states-schema 那一層反而不必動——逐態信號數 12–14,槽位對稱,沒有這個問題。

共同提案 · 判讀登記表

上面四條都是從敘述文字裡人工數出來的,因為沒有結構化欄位。建議每次判讀記一列去識別中繼資料:素材類型 / 次型、判讀對象層級、成卦階(六爻 / 半象 / 三爻 / 不成)、內外卦、動爻數、爻疑數、是否觸發警示、三值回饋、判讀者是否已知結局。真實素材與逐字引文照舊不入 git,但這些欄位沒有一個會洩漏素材內容。

一 · v0.2 的「達標」沒有數字已裁定 2026-08-03

升 v0.2 的唯一途徑是真實素材雙盲收斂達標。雙盲已跑三輪,校準素材累計 30+ 件,但門檻只有「收斂達標」四字:沒有數字、沒有算法(一致率的分母是什麼、引文重疊怎麼算)、沒有樣本數。

清點時另外發現一件事:三輪雙盲沒有一輪測的是這個門檻要的數。#1 測內卦、#2 測格級(83%)、#3 驗爻疑機制——全部打在透鏡層(lens-schema)。而 v0.2 的門檻掛在 states-schema,要的是八態 presence 一致率。也就是說,這一層的指標至今無任何測量值。

裁定(Simon,C 案):算法定死、門檻留人判、判定留痕。

  • 算法定死——逐態 presence 三值一致 ÷ 8;引文重疊限兩盲皆判「有料」且態別一致者,看是否至少共用一句逐字引文。透鏡層同精神、單位改六格。
  • 門檻不寫數字——樣本仍少,此時訂數字即假精確,違「寧可少說、不可亂說」。達標與否由 Simon 逐輪判定,判定須附一句指得回數字的理由。
  • 判定留痕——每輪必須算出指標並記進 CALIBRATION.md 的收斂指標紀錄表;跑過≠測過,沒有數字的輪次不計入升版之路,兩層不可互充。

已落地:兩份 schema 新增 convergence 區塊(算法為 canonical)、CALIBRATION 新增指標紀錄表(補記 #1–#3 現況與 #4 待跑)、SKILL 步驟 5 改為指向 schema 不複寫算法。下一步是雙盲 #4,標的必須是八態 presence,否則門檻無樣本可對。

二 · 主體同一性靠自律,不靠規則已裁定 2026-08-03留一問待裁

六案壓測的唯一破口。適用域三條件裡,缺行為證據與缺語用正當性都有現成規則會讓引擎自停;唯獨缺主體同一性不會停——羅馬案形式檢查全綠、每爻跨世紀衝突訊號,合規地聚合出對立判讀。

規則層追測(本次新發現):回填的爻疑氾濫規則(爻疑 ≥3 → 拒判)原是為此破口而設,但照條文推演攔不住羅馬案。同爻雙訊號裁決 的觸發條件是「同一爻同現亢與溺訊號」,而跨世代聚合最可能產生的是剛與柔同現——剛↔柔 衝突在規則表裡沒有這一格。判讀者只能擇一定案,爻疑數 = 0,氾濫規則永不觸發。破口成因因此更具體:缺一格規則,不只是缺紀律。(此為條文推演非重判;真正迴測需原始素材,已列待辦。)

裁定:把自律變成宣告,不變成數字。必宣告新增第三項主體同一性——問「這份素材裡的行為者,能否對彼此的行為負責或回應?(是/否/不確定)」,答否或不確定即拒判並附拆分建議。引擎偵測不到主體同一性,但可以要求宣告者說出來,同 G8「使用者宣告,系統不猜」的既有模式;不確定就停,是誠實的預設。

明文不採數字門檻(如「時間跨度 > N 年自動停」):N 從何而來?跨兩個半世紀好判,一家公司的十年史不好判;訂數字會同時誤殺合法素材與放過界外素材,理由同待議題一的假精確之戒。

已落地:lens-schema 宣告體系.必宣告 加第三項、SKILL 步驟 3、SOP 步驟 2、BOUNDARIES §2 追記。留一問待裁:剛↔柔 同爻並現要不要比照亢/溺 標爻疑?(動判讀紀律,需逐條核准。)

三 · 「設計樣態剛柔」要不要立項已裁定 2026-08-03 · 凍結

民法總則案的副產品:讀文本設計而非運作,剛柔並濟的設計讀之成理。能力是真的,應用面不小(制度設計、契約、章程、產品規格皆為被設計出的靜態物件)。

裁定:凍結,但把存照升級。不立項的三個理由,重要性遞增——

  1. 它不是八態鏡的一個模式,是另一套判讀學。適用域三條件(單一運作主體 × 行為證據 × 同一時段)對讀設計整條不適用:靜態物件無主體、無行為、無時段。連邊界地圖都要重畫,不是加個開關。
  2. G5 會失去意義。本鏡整個靠「每條判定指得回行為引文」撐著;讀設計時引文指的是條文本身,而條文不是行為證據,是被設計出的物件。同一塊「引文可查」招牌底下換了東西——這是誠實印章最容易貶值的路徑。
  3. 地基未驗收。states-schema 仍在 v0.1,升 v0.2 的算法今天才定義,第一個有效樣本(雙盲 #4)還沒跑。此時開第二套判讀學=地基驗收前蓋第二棟樓,且稀釋得來不易的 30+ 案校準能量。

解凍三條件(需同時滿足):① states-schema 已升 v0.2;② 有具體需求推著、不是好奇心(參 NEIGHBORS 窗十:mission 是分析後的結論,不是起點——「我們發現可以做」不構成立項理由);③ 立項時另立工具、獨立 schema、不共用 canonical 判準,並列轉介不做對映(平台第一原則在工具層的落法)。

已記下的反面:若出現付費需求要讀契約或制度設計,凍結等於推掉生意;該情形改列第二優先,但觸發者必須是帶著素材來的需求方,不是我們自己。存照全文見 BOUNDARIES §4.1。

四 · 缺的不是外池,是雙池齊備的素材已裁定 2026-08-03迴測待跑

原本的說法是「外池永遠薄」——邊界壓測界內三案全出半象,公開素材天然偏內部治理紀錄。但日用第一案給了鏡像反例:最厚的一份聚合交付文本,外池厚實而內池零證據,一樣退半象。問題不是某一池薄,是素材體裁天生偏一邊:內部報告型外池薄、聚合交付型內池零、宣言型內池薄——單一體裁幾乎不可能雙池齊備。這是結構,不是運氣。

更正一句本頁原本寫過的話:「組合拳會不會違反主體同一性律」講得太重。該律針對的是跨主體跨世代聚合;同一組織、同一時段的多份素材並不違反它。真正的限制較窄,見下方三條界線。

還沒查的關鍵事實。五個六爻成卦全在第一輪(股東信、事故調查報告、深度個案史——這些體裁確實兩邊都寫),但都在判讀紀律六律上線之前判的,而六律裡就有成爻門檻 ≥2 句獨立引文。沒人知道那五案在現行規則下還撐不撐得住六爻。撐得住 → 六爻只是選材問題;撐不住 → 現行紀律下六爻實質不可達,而六爻層加 64 卦需求表是引擎最大最新的一批規則,份量比表面大得多。

裁定三件:

  1. 先迴測一案(決定性)——取挑戰者號羅傑斯報告或 Bezos 2016 股東信,以 v0.3.3 重判。素材公開、成本低,結果直接決定六爻層的定位。已入 CALIBRATION 待辦(下站)。
  2. 「降級」改述為「解析度階梯」——四階代表這份素材給得起多細的照,不是成績單。資料顯示半象是單一最大宗(29 案中 13 案);把階梯講成降級會誘使判讀者為「升到六爻」勉強湊證據,正好違反成爻門檻的精神。半象與不成卦同樣是有尊嚴的輸出。
  3. 組合拳三條界線——若以多份素材補另一池:① 同一運作主體;② 同一時段,時段由宣告者宣告、系統不設數字(同待議題一的反假精確原則);③ 同一爻的 ≥2 句引文不得跨檔拼湊,該爻要嘛靠 A 檔獨立成立、要嘛靠 B 檔。第三條是技術護欄:用兩份素材的證據合成一個判定,是最容易星座化的地方。

五 · 兩層雙假說印章疊在一起已裁定 2026-08-03

六爻版本身是工作假說待收斂,它依賴的 64 卦需求表 v0.1 又未經易學專家終審——兩個「待考」相乘。裁定前先做了一份資料稽核(64 列全數程式清點,可重算),結果改變了問題的形狀。

曝險其實接近零:待議題四查出六爻自六律上線後一次都沒成過,所以 64 表在現行規則下從沒被實際引用過。不是正在出貨壞東西,是還債要趕在六爻再次啟用之前。

真正該先想清楚的是:「終審」能審什麼。依據欄引的是經典(彖 61/64、象 59/64),但「象『自強不息』→ 召喚乾態與震態」這一步是我們的框架——八態不是易學的既有語彙。專家能審引文有沒有引錯、解讀偏不偏;審不了翻成八態這一步。把整張表講成「已專家終審」,等於借他的權威覆蓋我們自己的構造。

裁定四件:

  1. 拆印章——64 表引用分兩類:可溯源(經典引文、卦旨、時勢基調,可被終審)與自造橋(召喚/節制的八態對應,終審永不覆蓋)。
  2. 終審 scope 收斂到 27 卦——稽核發現召喚態全落在內外卦內者 31 卦可機械推導、無詮釋風險;超出的 27 卦才是風險集中處。且只審「解讀是否偏離原典」。
  3. 不整段降級,改逐項標記——六爻輸出中引自 64 表的內容逐項標明屬哪一類。比「終審前只給卦旨」精準,保住召喚對照的價值。
  4. 自造橋自己驗——schema 原有「咬不上=分歧素材記 backlog」即其收斂機制,本次正式化:記錄咬合/咬不上次數,累積後才談可信度。借不到別人的印章,只能自己走過。

稽核另外翻出三個先修項(資料工作,不需終審、不動判準):節制欄僅 7/64 有態標記,致「節制而正強=第一級警訊」在 57/64 上實質不可執行;「待考」機制寫了 0/64 使用;八純卦中唯一未把本股標成召喚的是艮卦。全文見 2026-08-03-bagua-64-table-audit.md。

九 · 迭代只有收斂管線,沒有存異管線討論提出

期待是:在演進裡看得到不同視角,甚至典範轉移。但現行機制把分歧當雜訊處理——雙盲的目的是收斂,分歧的唯一去處是「回填混淆對照」,也就是被消化掉;升 v0.2 的門檻又是收斂達標。制度上獎勵收斂,不記錄被頂翻的地方。

NEIGHBORS 窗十一寫的卻是相反立場:質疑與挑戰能讓不易注意到的前提浮上檯面,而該窗的「異」欄自己就寫著「他終須收斂成一個決策;我們可並列存檔蓋待考章」——存異是寫在筆記裡的承諾,流程裡卻沒有這一格。現成證據:案 2 頂出來的「設計樣態剛柔」是真正的視角轉移候選(讀文本設計而非運作),無處安放,只能標「未立項」。

風險不是抽象的:只收斂不存異的迭代,長期會把自己推向不可否證——那正是 BOUNDARIES 對惡性失敗的定義,只是發生在制度層而非單次判讀。

要討論:分歧三分流要不要寫進進化流程?(a) 判準沒說清 → 收斂,回填混淆對照(現行唯一路徑);(b) 判準沒錯、兩讀都成立 → 並列存檔蓋待考章,即爻疑的組織版;(c) 分歧指向「這套判讀學被素材頂到了」→ 立為典範候選,獨立列冊。零件已經有三個,缺的是接成一條與收斂並行的管線:爻疑兩讀並列(單次判讀層)、對立卦替換測試(目前只用於邊界壓測,可常態化)、NEIGHBORS 引進外部典範且明文並列不對映(防止典範被同化)。另可加一種異視角雙盲:同素材、不同宣告(換判讀對象=換界),得出不同卦不是雜訊而是視角——界隨對象移動本來就是規則寫好的。

十 · 補安側錨點(最便宜的一次修訂)資料觀察

歸格例句庫 6 條實質錨點全為亢 / 溺,零條示範「安」;理層僅 1 條且為溺。動爻的定義就是呈亢或溺之爻,錨點只給病理範例就會往病理靠,同時與語氣律「先力量後缺口」相衝。建議:補安側錨點,每爻至少剛 1 / 柔 1。例句庫只增不減、不動定義本體、不碰 G1–G8,是四條資料觀察裡風險最低、可最快執行的一條。優先補理層——它最缺,也最影響態分布(見資料觀察二)。

十一 · 結局盲判與判讀登記表資料觀察

兩件互相搭配的事。結局盲判:候選假說「動爻數=嚴重度」目前在資料裡與已知結局完美分離,無法區分讀出嚴重度與知道結局;要驗證得選判讀者不知結局的素材,或蓋掉可識別資訊只留運作語料。這條該在假說寫進規則之前做,否則等於把選擇效應固化成判準。

判讀登記表:記去識別中繼資料(素材類型 / 次型、成卦階、內外卦、動爻數、爻疑數、警示觸發、三值回饋、判讀者是否已知結局),真實素材與引文照舊不入 git。有了它,資料觀察四條才從觀察變檢定,待議題一的分母也才存在。
