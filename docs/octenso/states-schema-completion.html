Define 層補完
states-schema 八態量產

STATES-SCHEMA COMPLETION · 2026-07-15 · DEFINE LAYER

背景與目的

八態能格往 R/GA「Define → Encode → Deploy」三層發展。現況是 Define 層最單薄: octenso-states-schema-v0.1.yaml 只完整填了坎、離兩態,其餘六態是 stub; 且 schema 的坎/離主稱呼與素材倉術語對照表不一致。

Define 沒立穩,Encode 層的透鏡 agent(判讀依據=本 schema)就跑不準。 本輪把 schema 補成八態完整版,並用合成素材乾跑一次雙 agent 判讀, 在實地測試(八態應用測試手冊 v0.1)之前先除錯。

定案決策

Decision 1 · 命名以素材倉為準
坎主稱呼=沉澱者(坎)、離=明現者(離)。 schema 現行的「探索者/照見者」是漂移,改回。雅稱不動(坎=探索、離=照見)。 依據:material-pool 術語對照表+2026-07-14「沉澱」撞詞決策。
Decision 2 · 坎/離範本確認通過(驗收 step1 達標)
欄位=識別信號(語言/會議/BP/制度線索+正例引文形狀)、缺席判定、低載信號、 失衡信號(待審閱)、成熟表現(待審閱)、混淆對照、禁止推論。照此範本量產六態。
Decision 3 · 範圍=量產+合成素材乾跑
目前無真實素材;正式收斂測試(驗收 step2–4)留待實地測試產生素材後另開一輪。

工作內容

① 命名修正

kan.主稱呼: 探索者(坎) → 沉澱者(坎)
li.主稱呼: 照見者(離) → 明現者(離)

② 六態量產(乾/坤/震/巽/艮/兌)

每態補成坎/離同款完整結構。內容來源三層,全部可追溯:

schema 欄位來源狀態標記
主稱呼/雅稱/英文候選/系統/分支動詞素材倉術語對照表(照抄)已定案
一句話素材倉 A-4(照抄)原始
核心提問素材倉 A-9(照抄)原始
失衡信號/成熟表現素材倉 A-11,過三道翻譯規則待審閱
分支角色/識別信號/缺席判定/低載信號依 model-spec 卦德推導撰寫(新創作)原始 · Simon 重點審
混淆對照先推導易混對,乾跑分歧回填原始
禁止推論依 G1/G5 逐態寫原始

混淆對照初步易混對(乾跑後修正):震vs乾(都「發動」)、巽vs兌(都「柔性影響」)、 艮vs坤(都「守住」)、乾vs巽(都「推進改變」)、坤vs兌(都「接住人」)、 震vs艮(一動一停,失衡時互為誤判);各態 vs 坎/離缺的補齊。

紅線:G1–G8 護欄一字不動;主詞永遠是「運作」;缺席≠弱; verdicts / output_spec / working_hypotheses / acceptance 區塊結構不動。

③ 合成素材乾跑(除錯,不是正式驗收)

  • 素材:自寫仿真素材(創業 BP 節錄+產品會議紀錄,約一頁半), 埋標準答案:三態有料、兩態薄、三態缺席、一組失衡疑似(含「離過載+坎缺席」高風險組合)。
  • 判讀:兩個獨立 agent(互不知對方),各自只拿 schema+素材,依 output_spec 輸出。
  • 對答案:presence 一致率、引文重疊度、失衡 flag 命中;分歧回填混淆對照。
  • 產出:素材+兩份判讀+分歧分析,存 specs 附件,供實地測試前參考。

④ 版號與 meta

版號 0.1-draft → 0.1(拿掉 draft)。不升 v0.2——驗收計畫寫明 v0.2 需真實素材收斂達標,誠實守住。meta.filled 八態全列、meta.stub 清空。

⑤ 驗證

最小 schema 檢查:python3 可 parse、八態欄位齊全、G1–G8 未被改動、 主稱呼與素材倉術語對照表一致。沿工程慣例(無 node,python3 即可)。

不做的事

  • 舊頁命名回填(persona v1、overview 用語對齊)——另一筆債,另開輪。
  • 英文名定案(維持「未定案,不上線」)。
  • 伴讀 worker.js / 透鏡 agent 接上 schema——Encode 層的事。
  • 結構頁 v0.1 改版;material-pool 除回報錯誤外不改動。

完成的定義

  1. schema 八態完整、命名與素材倉一致、護欄不動、驗證通過。
  2. 乾跑產出三件套齊(素材/判讀×2/分歧分析),分歧已回填混淆對照。
  3. PR 進 main;COMPENDIUM 索引同步一行。
與 Simon 對談定案於 2026-07-15。乾跑素材為合成,收斂數字僅供除錯,不構成正式驗收; schema 升 v0.2 仍以真實素材收斂達標為準。
