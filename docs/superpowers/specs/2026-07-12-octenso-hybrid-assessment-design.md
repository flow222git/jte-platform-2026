## 0. 紅線(本 spec 的第一決策)

> **題庫負責測量,對話負責選路。對話可以決定「接下來測什麼」,永遠不能「打分數」。**

這是「AI=伴讀不是主筆」在測量上的對應版本。分數必須來自固定量尺的結構化題目——可追溯、確定性、可重現(同一串作答永遠得到同一份報告與同一組分享碼)。一旦讓 AI 從自由對話「聽出」分數:換個聊法分數就變、無法重測、無法試測統計、無法對任何人交代分數怎麼來。守住紅線,半題庫半對話是加分;越過紅線,公信力歸零。

## 1. 角色分工

| | 題庫(結構化題目) | 對話(伴讀) |
|---|---|---|
| 職責 | **測量**:產生分數、觸發判讀 | **導流**:發現線索、推薦下一個模組 |
| | 校準:能格追問(現行) | **潤語境**:解釋題目在問什麼、安撫作答焦慮 |
| | | **收回饋**:像/不像 摘要(現行) |
| | | **陪讀**:報告討論(現行) |
| 禁區 | 題目不追問生活細節(那是對話的事) | **不打分、不改分、不下診斷、不預測** |

對話「選路」的輸出只有一種:**推薦(或開啟)某個結構化模組**。就算未來把作答嵌進聊天視窗,答的也是固定量尺的選項按鈕,不是讓 AI 解讀自由文字。

## 2. 架構:固定核心 + 分支模組 + 對話導流

```
① 固定核心題庫(v2 的 28 題,人人相同)
      → 八態分數、四道門、能格 → 主報告、B 碼
      【唯一可跨人比較、可入分享碼的分數來源】
② 規則觸發的追問(現行能格校準)
      → 亢/潛才追問——自適應的第一層,照舊
③ 伴讀對話(讀報告、聊生活)
      → 發現線索:「你三句不離工作」「這段感情讓你很緊」
④ 分支模組(依 ③ 的線索或使用者自選,結構化小題組)
      → 對境耗能·工作 / 對境耗能·愛情 / 場景耗能 / 澄清微模組…
⑤ 模組結果以「並列註記」掛回報告
      → 補充鏡頭,不回灌八態主分數(C1:並列不捏因果)
      → 之後可再回 ③ 繼續聊,形成循環
```

**順序鐵律:固定核心永遠第一關、先測後聊。** 對話在前會暗示答題方向(框架效應);現行動線(測→報告→聊)剛好正確,不得倒置。

## 3. 分流訊號(「依使用者的反應」的三種來源)

| 訊號 | 來源 | 觸發方式 | 例 |
|---|---|---|---|
| 報告訊號 | 規則引擎 | 確定性規則(現行能格校準即此類) | 兩可篤定 → 澄清微模組;雙峰 → 二選一加測 |
| 對話線索 | 伴讀 | 伴讀依守則**推薦**,使用者點頭才開 | 聊天多次提到職場 → 推薦「對境耗能·工作」 |
| 使用者自選 | 選單 | 報告尾模組清單,想測就測 | 「我想看看感情那塊」 |

三種訊號一律**只開門、不塞人**——模組永遠是邀請,不是必經關卡。

## 4. 模組槽規格(銜接題庫池 spec)

每個分支模組是題庫池裡的一個「模組槽」:

```
module = {
  id: 'ctx-work',                    // 模組 ID
  title: '對境耗能 · 工作',
  ask: '這份工作正在需要你什麼?',     // 一句話說明(邀請語)
  trigger: {                         // 三種分流訊號的掛法
    rule: null,                      // 報告訊號(如 conf==='mixed')
    chat: ['工作','上班','老闆','同事'], // 伴讀線索詞(推薦用,非硬觸發)
    menu: true                       // 是否進自選清單
  },
  items: [...],                      // 題目(進題庫池管理:id/status/證據)
  scale: 'freq6',                    // 固定量尺
  output: 'annex'                    // 輸出=並列註記(不回灌主分數)
}
```

- 模組題目與核心題庫同樣走 `status: 池→試測→正式/退役`,同樣累積試測證據。
- **輸出格式只有 annex(並列註記)**:模組結果自成一小節掛在報告尾,寫法比照二選一對照(標註式)與對境耗能 spec(場域需求 × 你的底色,並列呈現)。
- 模組作答同樣只存 localStorage;是否併入分享碼是之後的戰略決定(預設不併,B 碼不變)。

## 6. 三階段路線圖

- **Phase 0 · 伴讀轉介(現架構即可,幾乎零成本)**
  Worker 系統提示加一段轉介守則(聽到場域線索 → 溫和推薦模組連結);報告尾加「還想多懂哪一塊?」模組選單。對話還不嵌作答,點連結去答題。
- **Phase 1 · 首批模組上架**
  §5 的四類模組按模組槽規格入池、接上三種分流訊號;模組結果以 annex 掛回報告。
- **Phase 2 · 對話內嵌作答**
  聊天泡泡裡出現固定量尺的選項按鈕(結構化,非自由文字);Worker 協定擴充一種訊息型別(`module_item`),作答仍記在 localStorage。體驗上才真正「半題庫半對話」。

## 7. 憲法對應檢核

- **AI=伴讀不是主筆** → §0 紅線:對話零打分;報告與註記全由規則引擎組裝。
- **C1 並列不捏因果** → 模組結果=annex 並列,不回灌、不解釋成因果。
- **誠實印章** → 模組各自掛「v0.x 研究假設·待考」;推薦語不得誇大(「要不要看看」而非「你需要」)。
- **作答不上傳** → 模組作答 localStorage;對話與選路走 Worker(頁面已揭露,不儲存對話,僅回饋摘要回傳)。
- **鏡子非算命** → 分流訊號描述現況(「你常提到工作」),不預測(「你工作會出問題」)。

## 8. 待決事項

1. Phase 0 轉介守則的措辭(伴讀怎麼開口才不像推銷)——待潤。
2. 模組結果是否給獨立小碼(例:`M1` 前綴)供重測對照——傾向 Phase 1 末再決定。
3. CTX 80 題翻修的優先順序(七個場景先修哪個)——建議照試測回饋的場域熱度。
4. 澄清微模組的觸發門檻(兩可篤定的定義沿用現行 conf==='mixed' 即可?)——Phase 1 定。
