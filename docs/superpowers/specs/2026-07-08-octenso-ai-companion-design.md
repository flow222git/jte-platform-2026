# 八態能格 · AI 伴讀設計 spec(第一階段:零後端)

整理日期:2026-07-08 ｜ 狀態:第一階段已實作於體驗頁
定位:AI 在八態能格的角色=**伴讀,不是主筆**——正式報告永遠由規則引擎組裝(可追溯、確定性、零後端);AI 負責報告讀完之後的開放討論。
上游:解讀憲法(C1–C8)、`octenso-claude-read-demo.html`(早期雛形)、2026-07-07 comparison spec 中「AI 該在的兩個位置」的決策。

---

## 1. 為什麼報告本體不接 AI(重申既定決策)

1. LLM 天性擅長「似是而非的因果」——恰是 C1 防的東西;規則引擎每句可追溯,AI 每次生成都是新的違憲風險。
2. 零後端、作答不上傳是產品北極星;內嵌 AI = 資料出境+金鑰+費用+維運。
3. 測量鏡需要確定性:同分數同報告;LLM 有隨機性。
4. 型錄補完後內容庫已夠厚,規則組裝已能出細膩報告。

## 2. 第一階段:伴讀包(已實作)

**機制**:報告尾新增「AI 伴讀」區——一鍵複製「伴讀守則(prompt)+報告全文(純文字版)」,使用者自行貼到慣用的 AI(Claude/ChatGPT/Gemini 連結並列)。零後端、零金鑰、隱私自主(使用者自願貼出,頁面明示揭露)。

**伴讀守則(核心資產,canonical 於 `bagua-v2-data.js` COMPANION)**——解讀憲法的 AI 行為版:

| 守則 | 對應憲法 |
|---|---|
| 陪讀者不是算命師;不預測、不斷吉凶、不下診斷 | C5、北極星 |
| 報告=此刻快照,不是定義;不叫使用者「某某型的人」 | C6、身分=格局 |
| 不編報告裡沒有的因果機制 | C1/C3/C7 |
| 高低過不足皆樣態,不評價;平實具體關懷 | C8、voice |
| 多問具體場景、認真對待「不像」 | felt-self、反 Barnum |
| 「該怎麼辦」先回到報告建議,再化為很小的下一步;不開人生藥方 | 解讀憲法治理精神 |

**報告純文字版**(`buildReportText`):與畫面同源組裝——峰名/八態分數與六級(含篤定)/四對判語(含二選一對照)/能格判定/主峰章節全文/雙峰或格局文/缺口潛段/三個方向。

**同場加映:「接下來 · 三個方向」報告區**(使用者提議的建議層):
- 好好用=主峰的中正發揮一句(DIRECTIONS.use,字根=中正詞庫)
- 留意收=能格判「亢」者的 aOver;無亢訊號則如實說明(C7)
- 值得練=缺口的 aUnder
三者全由既有素材組裝,無新機制宣稱。

## 3. 護欄與誠實揭露(頁面文案已含)

- 複製後內容仍在裝置上;貼給 AI=把報告交給該服務,自行斟酌。
- AI 回覆屬延伸討論,不是報告的一部分。
- 伴讀守則對 AI 是「請求」不是「保證」——AI 仍可能違規;守則把機率壓低並給使用者辨識基準。

## 4. 第二階段(backlog,俟試測回饋與預算)

- 內嵌對話:serverless 代理(Cloudflare Workers/Vercel)+ Claude API;需金鑰管理、用量上限、濫用防護,並修改隱私聲明(報告文字將送至 API)。
- 受限生成模式:AI 僅可引用型錄段落+重組銜接句;C1–C8 自動 lint 後才顯示。
- 觀測:伴讀包複製率、使用者回饋「AI 討論有沒有幫助」。
