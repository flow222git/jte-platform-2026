# octenso states-schema 補完(Define 層)設計

2026-07-15 · 與 Simon 對談定案

## 背景與目的

八態能格往 R/GA「Define → Encode → Deploy」三層發展(states-schema 檔頭已載明)。
現況:Define 層最單薄——`octenso/octenso-states-schema-v0.1.yaml` 只完整填了坎、離
兩態,其餘六態(乾坤震巽艮兌)是 stub;且 schema 的坎/離主稱呼與素材倉術語對照表
不一致。Define 沒立穩,Encode 層的透鏡 agent(判讀依據=本 schema)就跑不準。

本輪目標:把 schema 補成八態完整版,並用合成素材乾跑一次雙 agent 判讀,
在 Simon 實地測試(見八態應用測試手冊 v0.1)之前先除錯。

## 定案決策(Simon 拍板)

1. **命名以素材倉為準**:坎主稱呼=沉澱者(坎)、離=明現者(離)。schema 現行的
   「探索者/照見者」是漂移,改回。雅稱不動(坎=探索、離=照見)。
   依據:material-pool.md 術語對照表 + 2026-07-14「沉澱」撞詞決策。
2. **坎/離範本結構確認通過**(驗收計畫 step1 達標):欄位=識別信號(語言/會議/
   BP/制度線索+正例引文形狀)、缺席判定、低載信號、失衡信號(待審閱)、
   成熟表現(待審閱)、混淆對照、禁止推論。照此範本量產六態。
3. **範圍=量產+合成素材乾跑**(取徑二)。目前無真實素材;正式收斂測試
   (驗收 step2-4)留待實地測試產生素材後另開一輪。

## 工作內容

### ① 命名修正
- `kan.主稱呼: 探索者(坎) → 沉澱者(坎)`
- `li.主稱呼: 照見者(離) → 明現者(離)`

### ② 六態量產(乾/坤/震/巽/艮/兌)

每態補成坎/離同款完整結構。內容來源三層,全部可追溯:

| schema 欄位 | 來源 | 狀態標記 |
|---|---|---|
| 主稱呼/雅稱/英文候選/系統/分支動詞 | material-pool 術語對照表(照抄) | 已定案 |
| 一句話 | material-pool A-4(照抄) | 原始(潤稿備忘照留) |
| 核心提問 | material-pool A-9(照抄) | 原始 |
| 失衡信號/成熟表現 | material-pool A-11,過三道翻譯規則(主詞換分支、預測改問句、臨床字眼標記) | 待審閱 |
| 分支角色/識別信號/缺席判定/低載信號/正例引文形狀 | 依 model-spec 卦德+分支角色推導撰寫(新創作) | 原始(Simon 重點審這裡) |
| 混淆對照 | 先推導易混對,乾跑分歧回填 | 原始 |
| 禁止推論 | 依 G1/G5 逐態寫 | 原始 |

混淆對照初步易混對(乾跑後修正):
- 震 vs 乾(都「發動」:破局啟動 vs 定向開創)
- 巽 vs 兌(都「柔性影響」:滲透改變 vs 共鳴連結)
- 艮 vs 坤(都「守住」:定界喊停 vs 承載撐住)
- 乾 vs 巽(都「推進改變」:開新局 vs 鋪路徑)
- 坤 vs 兌(都「接住人」:承載培育 vs 交流回應)
- 震 vs 艮(一動一停,對待軸,失衡時互為誤判)
- 各態 vs 坎/離 已有部分(坎 vs 艮/乾、離 vs 兌/巽),缺的補齊。

紅線:G1–G8 護欄一字不動;主詞永遠是「運作」;缺席≠弱;
verdicts/output_spec/working_hypotheses/acceptance 區塊結構不動。

### ③ 合成素材乾跑(除錯,不是正式驗收)

- 素材:自寫仿真素材一份(創業 BP 節錄+產品會議紀錄,約一頁半),埋標準答案:
  三態有料、兩態薄、三態缺席、一組失衡疑似(含「離過載+坎缺席」高風險組合)。
- 判讀:兩個獨立 agent(互不知對方),各自只拿 schema+素材,依 output_spec 輸出。
- 對答案:presence 一致率(兩 agent 互比+各自 vs 標準答案)、引文重疊度、
  失衡 flag 是否命中。分歧處回填②的混淆對照欄。
- 產出存 `docs/superpowers/specs/2026-07-15-octenso-schema-dryrun/`
  (素材+兩份判讀+分歧分析),供實地測試前參考。

### ④ 版號與 meta
- 版號:`0.1-draft → 0.1`(拿掉 draft)。**不升 v0.2**——驗收計畫寫明 v0.2
  需真實素材收斂達標,誠實守住。

### ⑤ 驗證

  八態欄位齊全(每態含全部必要欄位)、G1–G8 未被改動、
  主稱呼與 material-pool 術語對照表一致。
- 跑法沿工程慣例(無 node;python3 即可,不需瀏覽器)。
