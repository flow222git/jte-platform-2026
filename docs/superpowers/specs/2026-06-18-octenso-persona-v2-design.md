# Octenso 八態能格 · Persona v2 設計 spec

整理日期：2026-06-18 ｜ 對象：`octenso/bagua-persona.html`（主 repo `jte-platform-2026`）
範圍：**一份大 spec、三塊**——① 報告改版 ② 耗能引擎（能格）③ 分享功能。
實作順序：① 報告 → ② 耗能（整體情境）→ ③ 分享。情境擴充（對境耗能）列為第二階段、本 spec 先框設計。

---

## 0. 背景與現況

- `bagua-persona.html`：24 題八態測驗 → 8 個分數 → 型＋八角雷達＋L1–L5 立體解讀。
- 現況「過頭／不足提醒」是**用分數高低推的**（最高極 `hiv≥70`→過頭、`≤40`→不足），等於假設「能量強＝用過頭」。本 spec 用**直接測量**取代這個推論。
- 現況「場域側寫」：同一套 24 題、換情境（工作/關係）再答，疊在底色上看落差。本 spec 第二階段會改寫它。
- 環境限制：GitHub Pages 靜態站、無後端、資料只在 localStorage、不上傳。
- 登入：`octenso-gate.js` 白名單擋全頁。
- 測試：無 node，`python3 -m http.server` ＋ chrome headless（讀 title 的 `RESULT pass=X fail=Y` 或 `--screenshot`）；頁面不可有外部絕對網址 script。
- 排版定案稿：`octenso/bagua-report-demo.html`（暫存，完成後移除）。

## 1. 核心模型（三層）

| 層 | 測什麼 | 怎麼測 | 輸出 |
|---|---|---|---|
| **八態** | 你有哪些能量、哪股強（容量/特質） | 24 題特質自評（保留現況） | 型＋雷達 |
| **耗能引擎** | 哪股被過用/不足/掏空（校準/成本） | 情境題 × 底色 | 過用/適中/不足 ＋「怎麼調」建議 |

- **能格 ＝ 耗能引擎套在「整體/平常」情境上**，是引擎的預設情境，第一階段實作。
- **對境耗能 ＝ 同一引擎換成「工作／關係…」情境**，第二階段，改寫場域側寫。
- 不做兩套會互相重疊的成本系統；能格不是一次性機制，而是耗能引擎的第一個情境。
- 八態特質題是地基（耗能＝情境需求 × **底色**，沒有底色就無從對），**不取代、不加特質題**。
- ※ 2026-08-05 能格統一 D3 註記:八態=**維度系統**(不是層)。「平常的你」指導語下測得=**配置層**(本檔所稱「特質/底色」即此,相對穩定);「此刻/場域」框架下讀=**狀態層**(lens/透鏡語境,可重測)。能格=掛在配置層讀數上的成本校準,與 COMPENDIUM §0 一致。

## 2. 報告改版（Feature 1，先做）

對象：結果頁渲染（`showResult` 及相關區塊）。視覺定案見 demo。

### 2.1 字級（老花友善）
- 內文基準 13 → **15.5px**；行高 1.7 → **1.85**。
- 次要灰字 `--muted` 加深一階（`#857c6d` → `#6f6657`）提高對比。
- 區段標題改用較大襯線。
- 新增 **A／A⁺ 字級切換鈕**：存 localStorage；預設 A，A⁺ 把基準放大到約 17.5px／行高 2.0。

### 2.2 編排（重排序＋分層折疊）
- 順序：型卡 → 雷達（獨立一屏）→ 精華 pull-quote（襯線大字）→ 你最鮮明的能量（優勢/盲點/成長）→ 四個系統 → 能量提醒 → 適合你的下一步 → **耗能·調校（新，見 Feature 2）** → **分享（移到最底）** → 用出去（測局/合盤/重測）→ 結語。
- **分享鈕從最上面移到讀完之後。**
- 深層段落用 `<details>` 折疊：四個系統預設展開；能量提醒、下一步預設收合。
- 視覺節奏：每段做成圓角卡片（surface 底＋線框）、襯線大標、區段留白。

### 2.3 換行（中文置中區塊）
- 對置中多行區塊（型卡精華、pull-quote、verdict 主句與提問）加 `text-wrap:balance`＋`line-break:strict`，消孤字尾行、減少切詞。

### 2.4 結果 vs 說明 區隔（每個系統）
- **說明區**（人人一樣，放淡）：系統名＋系統介紹＋軸線（如「乾·開創 ↔ 承接·坤」）。
- **你的結果面板**（你專屬，pine 左條＋淡綠底、圓角）：小標「你的結果 · ⟨狀態⟩」、強度條、verdict 卡、提醒。

### 2.5 強度條 ＝ 方案 A 雙向填色（取代單點 slider）
- 一條軌，左極從左端、右極從右端各自往中央填，填充長度＝該極分數。
- 語義：兩側都長且對稱＝雙邊都旺；兩側都短＝偏少用；不對稱＝偏一邊。松綠色、**不顯示數字**（低調、貼「測量鏡」）。同時編碼**強度（填多長）＋平衡（對不對稱）**。

### 2.6 分享區（底部）
- 鈕：複製連結／LINE／系統分享／下載 PDF。
- QR 縮圖 ＋ 誠實說明：社群自動預覽是通用卡、專屬視覺請用 PNG 圖卡。（細節見 Feature 3）

### 2.7 既有區段的安置
- `整合·立體的你`(L2+L3)、`人物速寫`、`場域側寫`、`確信度` 沿用同一套折疊卡片邏輯。
- 預設：維持目前相對順序、各自包成卡片；場域側寫留在下半（屬「把底色用出去」的延伸動作）。細節在 plan 階段定。

## 3. 耗能引擎（Feature 2）— 整體情境＝能格

### 3.1 流程
24 題八態 → 算分 → **動態挑極端態** → 對被挑中的股各問耗能題 → 出「耗能·調校」報告段。
（適性化 → 測驗變兩段：先八態算分、再依強弱丟耗能題。）

### 3.2 動態門檻（挑哪些股問）
- 分數 **≥ ~68 → 問過用**；**≤ ~35 → 問不足**。
- **上限取最極端的 3–4 股**，避免極端者爆量。
- 全平衡者 → 0 題；報告顯示「目前各態都在適中範圍」。

### 3.3 耗能題（關鍵：測成本，不是測更多特質）
- 每股 **2 題**，問「代價／張力／後果／後悔」，**不可**問「你多愛這股」。
- 範例（行動·過用）：「我常衝得太快，事後才發現做白工或要收拾。」「身邊的人有時跟不上我的節奏，覺得被我推著走。」
- 範例（喊停·不足）：「我常想停下來或拒絕，卻還是停不下來、不好意思拒絕。」「我很少替自己踩剎車，常拖到累垮才停。」
- 作答尺度沿用現有測驗的 Likert（plan 階段確認實際選項並對齊）。

### 3.4 判定
| 該股分數 | 耗能題回應 | 判定 |
|---|---|---|
| 高（≥~68） | 有代價 | **過用** |
| 高 | 沒代價 | **適中**（強但用得好） |
| 低（≤~35） | 有代價 | **不足** |
| 低 | 沒代價 | **適中**（不強但沒困擾，不急著補） |

### 3.5 輸出與報告
- 每個被標記的股：一句狀態（過用/適中/不足）＋一句「怎麼調」建議。
- 報告「耗能·調校」段落接在四個系統之後，只列被標記的股；無標記則顯示適中訊息。

### 3.6 內容撰寫（本功能最大的工）
- 8 態 × 過用題／不足題，以及 過用·不足·適中 各自的「怎麼調」建議文字。要寫得準、貼、可行動。

### 3.7 資料
- 新增 localStorage key（如 `bagua_cost_v1`）存耗能結果。

## 4. 情境擴充 — 對境耗能（Feature 2 第二階段，本 spec 先框）

- 改寫「場域側寫」：把「重答同一套 24 題」改為**每情境一套情境題**，測「這個情境需要哪些能量（demand）」。
- 耗能 ＝ 情境需求 vs 底色容量的落差：情境很需要、底色又低的股＝被掏空；情境需要、你又有＝順流。
- 輸出：該情境把你哪股掏空 ＋ 情境建議。同一耗能引擎、換情境腳本與鎖定邏輯。
- 內容工：每情境一套情境題＋「情境需求→八態」對應。
- 取代現行落差視圖；遷移細節與是否保留落差呈現，第二階段 spec 再定。
- **第一階段不實作**，先把能格（整體情境）做出來、驗證引擎站得住，再擴充。

## 5. 分享功能（Feature 3）

### 5.1 對方看到什麼
- **精華摘要落地頁 ＋ 可展開完整 L1–L5**。
- 精華：型＋雷達＋一句精華＋關鍵詞＋大 CTA「測你自己的能量」；可展開看完整解讀；另有「跟我合盤」CTA（重用現有合盤流程）。

### 5.2 資料與路由
- 沿用 `encodeCode`：`'B1'`＋16 位數字 ＝ 18 字元，整份報告由對方端用這 8 個分數**現算重建**（零後端）。
- **新增 hash 路由 `#r=CODE`（報告檢視）**，與現有 `#c=CODE`（合盤）區分。
- 選填名字：分享時可輸入，附在網址（如 `&n=` URL-encode）；留空＝匿名。

### 5.3 登入閘的例外（重要決策）
- 現況 `octenso-gate.js` 擋全頁；但分享的對方**不在白名單**。
- 決策：**`#r=`（與 `?r=`）的唯讀報告檢視繞過白名單**（唯讀、無真實後台資料、分享者自願公開）。
- 預設機制：`octenso-gate.js` 偵測到 `#r=`/`?r=` 即跳過白名單、直接 reveal。

### 5.4 管道
- 複製連結。
- 系統原生分享（Web Share API；手機面板含 LINE/IG/訊息）。
- LINE 專屬鈕（line.me 分享 URL，桌機也能用）。
- 下載 PDF（`window.print` ＋ 列印 CSS，免外部套件）。
- 沿用既有 PNG 圖卡（canvas：型＋雷達＋QR），**把圖卡的 QR/連結改指向新的 `#r=` 報告連結**。

### 5.5 限制（誠實揭露）
- 靜態站無 SSR → 社群**自動預覽卡是通用的**（分數在 hash，伺服器/爬蟲讀不到、無法依人客製縮圖）。
- 專屬視覺走 PNG 圖卡。動態 OG 圖（serverless）列 backlog、本次不做。

### 5.6 隱私
- 資料在網址 hash、純前端、不上傳（延續 localStorage 不上傳的精神）。
- 拿到連結者可見該份報告（使用者自願分享）。

## 6. 測試（無 node，延伸現有 persona 測試；目前 159 全綠）

- `encodeCode`/`decodeCode` round-trip；`#r=` 路由解析；`#r=` 繞過登入閘。
- 耗能：動態門檻挑股、判定表（過用/適中/不足）、上限 3–4 股。
- 報告渲染：被標記/未標記/全平衡三情況；A／A⁺ 切換；強度條填充比例。
- 維持「頁面無外部絕對網址 script」以利 virtual-time 測試。
